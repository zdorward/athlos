# Race Data System Redesign

**Date:** 2026-03-20
**Status:** Approved

## Problem

The current race data system has three issues:
1. Single `races.ts` file with a Canada-only schema (`province` field) — doesn't scale to other countries
2. The `verify-races` skill dispatches one web research agent per race, which is slow and prone to getting stuck
3. No USA race data; USA support was a stub

## Goal

A per-country file structure populated by a real API (RunSignUp for USA), with a simple seed script replacing AI-driven web research. Scope: full marathons and half marathons only.

---

## Data Model

**File:** `apps/web/data/races/types.ts`

```typescript
import type { Distance } from "@/components/onboarding/types"

export interface Race {
  id: string       // "{country}-{city-slug}-{distance}-{year}", e.g. "us-nyc-full-2026"
  name: string     // Official race name
  city: string
  region: string   // Province (CA), state abbreviation (US), equivalent elsewhere
  country: string  // ISO 3166-1 alpha-2, e.g. "CA" | "US"
  date: string     // ISO 8601, YYYY-MM-DD
  distance: Distance  // "half" | "full"
  url?: string
}
```

`Distance` stays in `@/components/onboarding/types` (unchanged — other onboarding code depends on it).

---

## File Structure

```
apps/web/data/races/
  types.ts       ← Race interface
  index.ts       ← combines all countries, exports RACES
  ca.ts          ← Canadian races (migrated from current races.ts)
  us.ts          ← US races (generated by seed script)

scripts/
  seed-races.ts  ← fetches and writes per-country race files
```

### `index.ts`

```typescript
import { CA_RACES } from "./ca"
import { US_RACES } from "./us"

export const RACES: Race[] = [...CA_RACES, ...US_RACES]
export type { Race } from "./types"
```

Adding a new country = add a fetcher, add a `XX_RACES` import here.

## Seed Script

**Path:** `scripts/seed-races.ts`
**Invocation:** `pnpm seed-races [country]` (e.g. `pnpm seed-races us`)

### USA — RunSignUp API

RunSignUp provides a public REST API at `https://runsignup.com/Rest/races`. Requires an API key and secret stored in `.env.local`:

```
RUNSIGNUP_API_KEY=...
RUNSIGNUP_API_SECRET=...
```

The script:
1. Fetches all US states in parallel (one request per state, filtered to `full` and `half` distances)
2. Deduplicates by normalized name + distance + year
3. Generates `apps/web/data/races/us.ts` — overwrites on each run
4. Output is sorted by date ascending

### Canada

The 34 existing races in `races.ts` are migrated manually (one-time). The seed script does not re-fetch Canadian data; `ca.ts` is maintained by hand or extended later with a RunGuides fetcher.

### Adding New Countries

Each country has a fetcher function in `scripts/seed-races.ts`. The entry point reads the `[country]` argument and calls the appropriate fetcher. No fetcher = error with a helpful message.

### Output format

The script writes a typed TypeScript file:

```typescript
import type { Race } from "./types"

export const US_RACES: Race[] = [
  {
    id: "us-boston-full-2026",
    name: "Boston Marathon",
    city: "Boston",
    region: "MA",
    country: "US",
    date: "2026-04-20",
    distance: "full",
    url: "https://www.baa.org/races/boston-marathon",
  },
  // ...
]
```

The file is committed to git. Changes are reviewed via `git diff` before committing — no AI judgment involved.

## App Changes

### `data/races.ts` → deleted
### `data/races/index.ts` → new entry point

All app imports update from `@/data/races` (already the correct path if `data/races/index.ts` exists — no import string changes needed as long as the barrel export matches).

### `step-find-race.tsx` and `landing-page.tsx`

`race.province` → `race.region` (search filter + display). Display format stays `{city}, {region}` — works for "Toronto, ON" and "Boston, MA" alike.

### `Race` type imports

Any `import type { Race }` from `@/data/races` continues to work via the barrel export in `index.ts`.

---

## Skill Changes

The `verify-races` skill is **removed** and replaced with a note in its `SKILL.md` directing users to run `pnpm seed-races [country]` instead. No more parallel web research agents.

---

## Migration Steps (in order)

1. Create `data/races/types.ts` with `Race` interface
2. Create `data/races/ca.ts` — migrate existing 34 races, add `country: "CA"`, rename `province` → `region`
3. Create `data/races/index.ts` barrel
4. Delete `data/races.ts`
5. Update all import sites (`step-find-race.tsx`, `landing-page.tsx`, any others)
6. Rename `province` → `region` at all usage sites
7. Build seed script (`scripts/seed-races.ts`) with RunSignUp USA fetcher
8. Run `pnpm seed-races us`, review output, commit `us.ts`
9. Add `pnpm seed-races` script to `package.json`
10. Update or retire the `verify-races` skill

---

## Out of Scope

- 10K or shorter distances
- Virtual races
- Race result data
- Countries beyond USA (future: same pattern, new fetcher)
